Data flows from the API into raw, is loaded into core, football and odds, and is summarised in analysis. football.fixtures is the hub: almost every match-level table and every odds table refers to it by fixture_id.

Design rules

  • Common IDs. Every primary key is the Sportmonks ID named <entity>_id, with the same name in every table that refers to it. Sportmonks' "participant" is always team_id; double references are prefixed (home_team_id, from_team_id, related_player_id).
  • One lookup for codes. Every coded value (event, statistic, position, official role, lineup type) is a type_id into core.types. Filter on the stable developer_name, e.g. 'YELLOWCARD', 'FOULS'.
  • Fixture context on child rows. Match-level tables carry league_id and season_id, filled by trigger from the fixture, so most queries skip the join.
  • JSON statistics with a numeric column. Original stat objects stay in data; a generated value column (core.jnum) can be summed or averaged directly. Odds get decimal_odds and probability_pct the same way.
  • Rebuildable. Raw API payloads can be kept in raw.api_responses so tables can be rebuilt without re-downloading.
  • Relationship map. raw.relationships lists every reference. It creates all foreign keys and indexes, and raw.missing_references() lists IDs still to fetch.

Keys and automation

MechanismWhat it does
Enforced foreign keysCompetition structure (seasons, stages, rounds, groups, aggregates to leagues/seasons), fixtures to leagues/seasons, every fixture child to fixtures, detail tables to their parents, and odds to fixtures. Deferrable, checked at COMMIT, ON DELETE CASCADE.
Indexed, not enforcedReferences to people, teams, venues, geography, types and sub-structures, which Sportmonks may mention before they are downloaded. raw.missing_references() reports the gaps.
trg_fixture_contextOn every table with fixture_id, league_id and season_id: copies league and season from the fixture on insert. Insert the fixture first (same transaction is fine).
trg_sync_home_awayOn fixture_participants: keeps fixtures.home_team_id and away_team_id in step with the participant's location.
Generated columnsvalue = core.jnum(data) on stat tables; decimal_odds and probability_pct = core.num(...) on odds tables.
